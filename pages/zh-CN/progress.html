公开进度摘要

用一页看懂 Roadmap 顺序和实作状态。

Mycel 目前仍处在窄版 first-client lane。M2 在当前窄版 replay/storage/rebuild 范围内保持关闭，因此 active lane 集中在 M3 / M4。M3 现在以 persisted relationship/current-governance summaries、store-index governance context、去重 policy catalog、point-to-point View diff 与可复用 profile 提示为基线继续推进。M4 也已在现有 production-replication、 sequencing、reachability、sender-validation 与 negative/warning proof set 之上，补上 accepted Snapshot/View metadata 与 fetched objects 的绑定，以及 document-scoped HEADS replace=true behavior。更广的 governance 工作与 session/capability/error-path interop 仍保持 open。

  1. 维持 M2 在当前窄版 replay/storage/rebuild 范围内的已关闭状态，并以 richer mixed content/metadata competing-branch rebuild/reporting proof 作为基线。
  2. 以当前 accepted-head reader base、profile discovery/error feedback 与 reuse hints、governance inspect/list/publish/current workflows、persisted relationship/current-governance summaries、store-index governance context、去重 policy catalog 与 point-to-point View diff 为基线，谨慎扩展 M3。
  3. 让 M4 保持窄范围，从当前 production-replication、sequencing/root gating、advertised Snapshot/View metadata binding、document-scoped HEADS replace=true、reachability、sender-validation 与 warning/error baseline 继续收敛 peer-store sync proof。

里程碑时间线

这份 roadmap 是串行推进的：后面的 phase 都默认前面的 phase 已经稳定。现在的重心是维持 M2 在当前窄版范围内的已关闭状态、M3 的谨慎扩展，以及剩余的 M4 互操作 proof。

  • Replay 和 state_hash

阅读器加治理

M3

早期部分完成
  • Accepted-head reader workflows
  • Bundle 和 store rendering，并保留 ancestry context
  • 命名 fixed-profile reading，并带有更清楚的 discovery/error feedback 与可复用提示
  • 具备 editor-admission 感知的 inspect/render flows
  • head inspection 中的 bounded viewer score surfaces
  • Filtered governance inspect/list/publish/current workflows
  • Persisted governance reverse indexes
  • 在 view inspect / view list 里可见的 persisted governance relationship summaries
  • 在 view current 里提供的 per-document current-governance summaries
  • 在 store index 输出里可见的 governance source labels 与 current-view context 摘要
  • 在 view inspect / view current 里可见的去重 governance policy catalog
  • 通过 view diff 提供的 point-to-point governance comparison
  • 剩余工作：超出 catalog/summaries 的更广 persistence、richer history/range 与 policy-aware tooling，以及进一步的 profile ergonomics
全栈

M4

早期部分完成
  • Wire validation 与 OBJECT body 检查
  • Session reachability 与 store-backed bootstrap
  • Peer-store 的 first-time / incremental sync proof
  • Capability-gated 的 SNAPSHOT_OFFER / VIEW_ANNOUNCE
  • localhost multi-process、re-sync idempotency、depth-N catchup 与 partial-doc selective sync proofs
  • 更广的 pre-HELLO / pre-root / pre-MANIFEST gating
  • HEADS 先于 MANIFEST 的 setup，以及 document-scoped HEADS replace=true
  • Accepted Snapshot/View metadata 在 storage 前绑定到 fetched objects
  • Stale root/dependency、stale snapshot 与 stale object WANT rejection
  • unadvertised WANT 与 unrequested OBJECT rejection
  • unknown-sender 与 HELLO sender-identity mismatch rejection
  • ERROR-before-HELLO acceptance，以及 explicit ERROR-only 与 unreachable WANT rejection proof
  • messages-after-BYE rejection 与 missing-BYE warning proof
  • 剩余工作：其他 root-set violations、unaffected-document in-flight provenance，以及更广的 session/capability/error-path proof
全栈

M5

  • Selective app-layer growth

实作矩阵

这张表把 checklist 压缩成 section-level 状态，让我们快速看到哪些部分已经大致完成、哪些仍然是 partial、哪些仍属于后续 phases。

领域 状态 里程碑 当前判断
1. Repo and Build Setup 完成 M1 这一块现在属于已关闭的 minimal-client gate；这里已经没有活跃的 follow-up。
2. Object Types and IDs 完成 M1 必需的 v0.1 families 与 minimal-client role modeling 现在都保留为已关闭 gate 的 proof，不再是活跃的 checklist debt。
3. Canonical Serialization and Hashing 完成 M1 minimal gate 所需的 canonical rules 与 shared helper reuse 已关闭；post-M1 的 wire follow-up 现在属于更广的 M4 lane。
4. Signature Verification 完成 M1 / M4 minimal gate 所需的 object 与 wire signature verification 已关闭；更广的 interop/error-path follow-up 仍在 M4。
5. Patch and Revision Engine 大致完成 M2 Replay 与 state_hash 已到位；dependency verification、wrong-type 与 multi-hop ancestry proofs、sibling declared-ID determinism，以及 render-path ancestry context 都更完整。
6. Local State and Storage 大致完成 M2 Store ingest、rebuild、indexes，以及可直接证明多文档 indexes 能在 index loss 后只靠 stored canonical objects 重建的 CLI proof 都已存在；local transport/safety policy 现在也会保存在独立的 local policy file，而 rebuild smoke 会同时保留 replicated indexes 与 local policy state。
7. Wire Protocol 部分完成 M4 Canonical wire-envelope parsing、field validation、sender checks、sequencing/head tracking、reachability gating、store-backed bootstrap、OBJECT verification、capability-gated optional messages、更广的 root gating、advertised Snapshot/View metadata binding、document-scoped HEADS replace=true、stale/unadvertised WANT 与 unrequested OBJECT rejection、sender-validation faults、explicit ERROR handling、messages-after-BYE rejection、missing-BYE warning proof，以及最小 peer-store sync driver 都已存在；更广的 session/capability/error-path proof 仍保持 open。
8. Sync Workflow 部分完成 M4 Peer-store 驱动的 first-time 与 incremental sync 已通过 mycel-core、CLI 与 simulator coverage 证明 shared verify/store flow，并覆盖 Snapshot/View fetching、localhost 与 production-replication proofs、sequencing/root gating、storage 前的 advertised metadata binding、document-scoped HEADS replace=true、stale/unadvertised WANT 与 unrequested OBJECT rejection、sender-validation 与 reachability faults、explicit ERROR handling，以及 messages-after-BYE / missing-BYE handling；更广的 session/capability/error-path proof 仍保持 open。
9. Views and Head Selection 大致完成 M3 Deterministic selector core、命名 fixed-profile selection 与更清楚的 discovery/error feedback 和 reuse hints、分开的 editor/view admission-aware flows、bounded viewer score channels、persisted relationship/current-governance summaries、store-index governance context、去重 policy catalog、point-to-point View diff，以及 direct selector regressions 都已存在；超出 catalog/summaries 的更广 persistence、richer history/range 与 policy-aware tooling，以及进一步的 profile ergonomics 仍保持 open。
10. Merge Generation 部分完成 M2 Replay verification 与保守型 local merge-authoring profile 已存在，涵盖 structural move/reorder、新 parent reparenting、简单 composed parent-chain coverage、更广的 nested structural matrix、更细的 direct/anchor-based placement reasons、更清楚的 metadata competing-branch 边界，以及 richer mixed content/metadata competing-branch 细节；当前窄版 M2 收口已经完成，因此后续工作可以留在 active M2 债务之外。
11. CLI or API Surface 部分完成 M2 / M3 / M4 Verification 与 authoring、editor-admission-aware reader inspection/render、带 persisted policy 与 relationship summaries 的 governance inspect/list/publish/current/diff、transcript-backed sync pull，以及内部 sync peer-store 都已存在，并覆盖 optional Snapshot/View flows、localhost 与 production-replication proofs、sequencing/root gating、advertised metadata binding、document-scoped HEADS replace=true、stale/unadvertised WANT 与 unrequested OBJECT rejection、sender-validation 与 reachability faults、explicit ERROR handling，以及 messages-after-BYE / missing-BYE handling。
12. Interop Test Minimum 部分完成 M1 / M2 / M4 Fixture isolation、reproducibility、parser/replay smoke coverage、直接的 wire-envelope/signature/session tests、peer-store 与 production-replication proofs、optional-message 与 localhost coverage、sequencing/root gating、advertised Snapshot/View metadata binding、document-scoped HEADS replace=true、stale/unadvertised WANT 与 unrequested OBJECT coverage、sender-validation 与 reachability faults、explicit ERROR handling，以及 messages-after-BYE / missing-BYE coverage 都已存在；更广的 session/capability/error-path cases 仍保持 open。
13. Ready-to-Build Gate 完成 M1 minimal-client gate 已关闭；剩余工作现在都改由 post-M1 follow-up checklist 追踪，而不是留在这个 gate。
